Project Health & Risk Tracker · Your code, explained

Understand it. Then explain it.

Start with one project and one risk. Learn the words, follow the actual code, then rehearse a short demonstration.

Begin with the purpose

“This program tells me which projects need attention.”

It holds three fictional projects. You can view their work, change a status, and ask a local AI to explain an open risk. C# calculates health. Qwen writes advice.

Your opening sentence

“My project is a console-based project health tracker. It stores tasks, milestones, and risks, applies simple rules to calculate health, and uses a local AI model to explain one selected risk. I’ll show the data structure first, then the rules, then how the menu connects everything.”

C# is the language these instructions are written in. .NET supplies reusable classes and runs the built application. Visual Studio helps us edit, build, and debug it. Bionic is a separate program that receives our local AI requests and uses Qwen to generate advice.

Class 3 · one piece of work

ProjectItem

Holds one task, milestone, or risk. Checks status changes and returns details.

Think: one entry inside a project's list.

None is a custom parent class. Inheritance means defining a class using another class as its starting point. The starting class is the parent or base class; the new class is the child or subclass. Here Project contains ProjectItem objects; it does not provide their class definition. Task, Milestone, and Risk are enum choices. All C# classes implicitly inherit from the built-in object type; we did not design our own inheritance hierarchy.

Seven words to learn first

Type
Tells C# what kind of value something can hold. int means a whole number; Project means a Project object reference. A class defines one kind of type.
Class
A definition of what something can hold and do. Project defines the information and actions for a project.
Object
One actual instance made from a class. The Project object named Inventory System has its own manager and items.
Variable
A named place to hold a value or a reference to an object. inventory refers to one Project object; count holds a number.
Property
A named value belonging to an object. inventory.Name is “Inventory System.” It is data you read or set, rather than an action you call.
Method
A named set of instructions that does a job. CalculateHealth() examines items and returns a result. Parentheses after its name call it.
Enum
A type with named choices. ItemType is the enum; ItemType.Risk is one choice.

A .cs file is a C# source file. It can contain a class, several classes, enums, or other C# code. Here, StatusTypes.cs contains three enums.

What comes back over the connection?

HTTP is the set of rules used to send requests and responses. The response body uses JSON: structured text with named values and lists. This tiny example shows the format, not a recorded model answer:

{"output":[{"type":"message","content":"Example advice."}]}

The code reads the output list, finds an entry whose type is message, and extracts content. It returns “Example advice.” to ReviewRiskAsync, which prints the text. Square brackets hold a JSON list; braces hold an object with named values.

0:00–0:45 · Purpose and map

Open with the problem

“This program tracks fictional project work. A task is a piece of work, a milestone is a checkpoint, and a risk is a possible problem. The program groups these under each project. I can update their status and see whether a project needs attention. I can also ask a local model for a short risk explanation. There are three application classes: Program coordinates the app, Project represents a whole project, and ProjectItem represents one task, milestone, or risk.”

0:45–1:15 · StatusTypes.cs · lines 5–27

Show the available choices

“I’ll explain the definitions before the entry point. This file contains enums, which are types with named choices. ItemType says what the item is; ItemStatus says its state; HealthStatus is the project's calculated result. These names avoid inconsistent text. The status method still checks which choices are appropriate for a risk versus a task.”

1:15–2:45 · ProjectItem.cs · top to bottom

Explain one item

“ProjectItem is a class: it defines what each item holds and can do. The scanner risk is one object made from this class. Its properties hold its own title, owner, type, status, and risk information. The constructor fills in starting values when new creates an object. Type stays fixed after construction. Status has a private setter, so outside code asks ChangeStatus to make a validated change.”

“GetAllowedStatuses returns the valid choices. ChangeStatus checks that list before assigning Status. CalculateScore multiplies likelihood by impact. For the sample scanner risk, four times five gives twenty out of twenty-five. That is a priority score, not an eighty-percent chance. GetDetails returns a readable description. It does not print anything itself.”

Why this design: one item class reduces files; the tradeoff is unused risk fields on tasks. This version has no custom inheritance hierarchy.

2:45–4:00 · Project.cs · top to bottom

Explain the whole project

“Project holds a name, manager, and list of items. A project contains item objects; it is not their parent class. The constructor gives each new project its starting values. CountOpenRisks loops through Items and counts only entries that are both risks and open.”

“CalculateHealth applies our classroom rules. An open risk with impact four or five immediately returns OffTrack. Otherwise any open risk or late unfinished milestone makes it AtRisk. Otherwise it returns OnTrack. A flag remembers a smaller problem while the loop continues looking for a high-impact risk. Health is recalculated from current item data, so closing a risk changes the next result. AI does not make this decision.”

4:00–6:30 · Program.cs · top to bottom

Connect the pieces

“Program.Main is the entry point. CreateSampleProjects returns a list of Project objects. In List<Project> projects, the first part is the type and projects is a local variable referring to that list. Main also creates one HTTP client for local requests. Its loop prints the menu, and switch calls the method matching the typed option.”

“ShowProjects prints current results. ReadProject and ReadItem translate typed IDs into existing objects. TryParse rejects non-numbers without crashing. UpdateStatus shows the selected item's allowed choices. It converts the user's one-based menu number to a zero-based list position, then calls ChangeStatus. The item in the project's list is the same object, so health can immediately be recalculated.”

“For AI, ReviewRiskAsync selects an open risk, previews its information, and asks for confirmation. GetLoadedModelAsync checks that our exact Qwen model is loaded. ExplainRiskAsync builds text from the selected information and serializes a request to JSON, a structured text format. HttpClient sends it to Bionic on this computer. await lets the code wait for completion before continuing. We extract the returned message and print it in the console. Errors return readable messages; they are not fake AI answers.”

“At the bottom, CreateSampleProjects calls our constructors and adds items to each project's list. It returns the three example projects. The data is in memory, so restarting resets it.”

8:15–9:00 · Tradeoffs and finish

Show you understand the limits

“This is a small classroom demo, so I kept three application classes and used fixed sample objects. It does not save edits or measure real-world risk. The score and health are simple rules; the local model only explains the supplied situation. AI wording can be wrong, so the app never uses it to change project data. The networking block is the most advanced part. In a larger application, I would separate that code again and add persistent storage.”

If asked about assistance, describe it honestly. Explaining and verifying the design is more useful than pretending to have written every line without help.
