Start with the job, then the code

A person changes a status. C# calculates health. AI explains the risk.

The console application stores three fictional projects. You choose one, view its information, change its task/milestone/risk status, or ask local Qwen for an explanation. The two classes divide those jobs.

Four names, four different jobs: C# is the language the application is written in. .NET supplies the runtime that executes it and reusable libraries such as HttpClient. Visual Studio is where you edit, build and run the application. Bionic runs the separate local model service that the application contacts.
Our class · Project

One project’s data and rules

A class defines what an object can hold and do. Project defines properties such as Name and RiskStatus, plus methods such as CalculateHealth().

new Project(2, "Inventory System", "Taylor Smith") creates one object using that definition. Its values belong to that object; another Project can have a different name and status.

Our class · Program

The sequence of actions

Main() is the method where execution begins. Program creates the sample objects, repeats the menu, reads your choices, calls the Project methods and communicates with Bionic.

Its methods are static: we call them without creating a Program object. A Project’s health method is an instance method: it uses the values belonging to one particular Project.

Your opening sentence

“Project defines the information and rules for one project. Program controls the menu and the local AI connection. C# decides the health category; AI adds an explanation of the supplied risk.”

Read one line without guessing what the words are

List<Project> projects = CreateSampleProjects();
List<Project>
The type: a .NET list whose entries refer to Project objects. The angle brackets specify the element type. This is not a method.
projects
A variable name. It holds a reference to the list. A reference is how the program reaches an object; it is not a new copy of the object.
=
Assignment: evaluate the right-hand side, then place its result in the variable on the left. It is different from ==, which compares two values.
CreateSampleProjects()
A method call. Run this named set of instructions. The empty parentheses mean the caller provides no arguments. The method returns the list.
;
The end of this statement. It does not mean the entire program has finished.

Watch the data change form.

The model does not receive a C# object. It receives a request containing text. The reply comes back as structured text that the program must unpack.

Project facts→ prompt string→ JSON string→ StringContent + POST→ response JSON→ printed text
Ready is more than downloaded: the file must exist on disk, a model instance must be loaded, the API must be listening, and only a chat request starts generation. This website’s server is separate from the model API.

8:00
0:00–1:00 · Data, creation and the starting point

Open Program.cs at Main

“This console app tracks three fictional projects, each with one task, milestone and risk. Project defines the data and rules for one project; Program controls the menu and AI connection. They are two classes, with no custom inheritance. ItemStatus and HealthStatus are enums: named choices.”

“Main is where execution starts. CreateSampleProjects uses new Project to create each object. The constructor sets its ID, name and manager, and the initializer fills the other properties. The method returns a List of Project references. Main also creates one HttpClient for later requests. The examples live in memory, so restarting resets them.”

1:00–2:00 · Menu, listing and details

Follow the first two menu options

“The while loop repeats the menu. ReadLine supplies text, and switch selects an action. ShowProjects loops through the list, calculates each project’s health, prints the row and counts the categories.”

“ViewProject calls SelectProject. That method reads an ID, checks the input and returns the matching existing object, or null for no selection. GetDetails prepares a description using CalculateHealth and GetRiskDetails; WriteLine prints it. The selected variable refers to the object already in the list, so it is not a separate copy.”

2:00–3:30 · Status input and project rules

Trace the value two

“UpdateStatus selects a project and section. GetAllowedStatuses provides Open and Closed for a risk. If I type two, TryParse produces integer two and reports success as a bool. A separate check validates the range. Subtracting one gives list index one, whose value is Closed.”

“ChangeStatus checks that value against the allowed list, assigns the status and returns true. Private setters keep those assignments inside Project. CalculateHealth uses the current facts: an open high-impact risk is OffTrack, another open risk is AtRisk, and a late unfinished milestone is AtRisk. Otherwise it returns OnTrack. It checks that an optional date exists before reading it.”

“CalculateRiskScore multiplies likelihood by impact. Twenty out of twenty-five is a priority ranking, not an eighty-percent failure probability. Health uses its separate rules.”

3:30–6:00 · The complete local AI exchange

Point to PostAsync and follow the result

“ReviewRiskAsync selects an open risk, previews the facts and asks for confirmation. It then awaits ExplainRiskAsync. Bionic runs Qwen separately from this C# app. GetLoadedModelAsync sends GET to the local models endpoint, matches the model key and returns a loaded instance ID. If none is loaded, the helper returns a setup message before sending chat.”

“The prompt combines the project name, C# health and GetRiskDetails text. A separate instructions string requests Risk, Why and Next action. JsonSerializer packages these strings and settings as JSON. In model equals loadedModelId, model is the API field and loadedModelId is our variable.”

“StringContent prepares the HTTP body. The actual generation call is client.PostAsync with the local chat URL and body. await supplies the resulting HttpResponseMessage. EnsureSuccessStatusCode checks the HTTP status before we read the reply.”

“I read the body into replyText, parse its JSON, and loop through output entries. Only message content is joined to the answer string. The helper returns it, and ReviewRiskAsync prints it. No model output is assigned to project properties. Expected network, timeout and JSON errors return readable messages through that same path. The menu waits until the operation finishes.”

6:00–8:00 · Demonstration and exit

Show each feature, with AI last

“I’ll list the starting states and open Inventory’s details. Closing its risk gives OnTrack. Completing Training’s overdue milestone gives OnTrack. I can show all three projects OnTrack, reopen Inventory’s risk, and request Qwen’s explanation. The wording can vary while C# health remains OffTrack. After the request returns, the menu repeats. Option five returns from Main and exits; break only leaves the switch.”
