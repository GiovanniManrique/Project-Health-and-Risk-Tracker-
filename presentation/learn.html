Project Health Tracker · read, follow, explain

Follow the code in the order it runs.

Whole code blocks. Plain-English meaning. Local Gemma inference with visible evidence.

Current version: Bionic serves Gemma locally. Fictional email, document, and metric files inform AI-proposed likelihood and impact. C# validates the reply, calculates scores, and ranks risks. This teaching page makes no model requests.

Small classes. Three projects. Evidence for each brief.

Program: run the console

Main creates the samples and local client, repeats the menu, validates selections, and displays results. Program's methods are static; no Program object is needed.

Project and Risk: stored facts

A Project contains one task, one milestone, and a list of Risk objects. Their methods validate statuses, calculate stored health and scores, and describe the records.

AiRiskService: request and check

The service reads the project's fictional files, sends one local model request, checks the returned estimates, and formats the ranked brief.

RiskEstimate: separate advice

Each estimate holds an AI-proposed likelihood, impact, reason, source IDs, and action. It does not replace a stored Risk. Its score is calculated in C#.

From evidence to a decision

Local .eml / .txt / .json files→ current project snapshot→ Gemma estimates 1–5 ratings→ C# validates and multiplies→ manager reviews the brief

Inventory's fictional evidence includes a six-day supplier delay, a $12,500 forecast against a $10,000 budget, 40% actual progress against 65% planned, and one available tester out of three planned. The model explains how supplied facts affect each risk. It must flag missing information.

Stored health and AI estimates

Any open risk with stored impact 4 or 5 gives OffTrack. Other open risks or an overdue unfinished milestone give AtRisk. Otherwise health is OnTrack. The brief does not change these stored values. Likelihood × impact gives a priority ranking; 20/25 is not an 80% probability.

Encapsulation and composition

Status setters are private, so callers use ChangeStatus methods. A Project contains a List<Risk>; this is composition, without a custom inheritance hierarchy. StatusTypes.cs contains two enums, which are named choices rather than classes.

C# is the language. .NET supplies libraries and runs the application. Visual Studio is an editor/build environment. Bionic runs the local model. Files simulate a mailbox; the application does not read real email or send messages. Status changes reset on restart.

Questions & commands

Where do I type these?

Visual Studio: open ProjectHealthTracker.slnx with .NET 10 installed and press Ctrl+F5.

Bionic: load Gemma 4 E2B and start Local Model API. The tracker defaults to http://127.0.0.1:1235/v1 and google/gemma-4-e2b.

Application console: 1 lists, 2 views, 3 updates, 4 creates an AI brief, and 5 exits. Press Enter after each choice. Selection prompts accept 0 to cancel.

PowerShell in the repository:

dotnet build ProjectHealthTracker.slnx -c Release
dotnet run --project Tests/TrackerChecks.csproj -c Release
dotnet run --project ProjectHealthTracker/ProjectHealthTracker.csproj
python presentation/build_guide.py
& .\presentation\Start-Guide.ps1

For a different local API configuration, set BIONIC_BASE_URL (including /v1) and BIONIC_MODEL before starting the application. The model must be available in Bionic. Rebuild after editing the source DemoData fixtures so they are copied to the output folder.

Live demonstration

  1. Start fresh. Enter 1 to show the three health categories.
  2. Enter 2 → 2 to show Inventory's three stored risks and their evidence IDs.
  3. Show INV-EMAIL.eml, INV-NOTES.txt, and INV-METRICS.json in the source DemoData folder.
  4. Enter 4 → 2. Point to the model identity, citations, proposed ratings, C# scores, and actions.
  5. Enter 3 → 2 → 3 → INV-1 → 2 to close the supplier risk. Inventory becomes AtRisk because two other risks remain open.
  6. Enter 4 → 2 again. INV-1 must be absent from the ranked estimates; INV-2 and INV-3 remain.
  7. Enter 2 → 2 to show stored ratings are unchanged by the brief, then 5 to exit.

Each arrow means press Enter, then enter the next value. The model's exact wording and ratings can vary. If a live request fails, show the error and explain it; label any saved earlier output as a recorded example.
