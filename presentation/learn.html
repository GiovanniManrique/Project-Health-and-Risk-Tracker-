Current version: the local-model connection has been removed. Risk scores and health are calculated by C# rules. No model or API key is needed.

Two classes. Three project objects. One menu.

Program: coordinate the application

Main starts the app, creates the sample projects, reads menu choices, and calls methods to display or update information. Program has static methods, so no Program object is needed.

Project: information and rules

Project is the blueprint. Each object has its own name, task, milestone, and risk. Its methods validate status changes, calculate health and score, and produce details.

Project website = new Project(1, "Company Website Update", "Jordan Lee");

Project is the class/type. new Project(...) creates an object and calls its constructor. website is the variable referring to that object. A method is a named operation, such as website.CalculateHealth().

Encapsulation

Status properties use public ... { get; private set; }. Outside code can read their values, but must call ChangeStatus to change them. That method checks the allowed choices first. Other public properties do not have the same protection.

Enums are named choices

StatusTypes.cs contains ItemStatus and HealthStatus, both enums. A .cs file is a C# source file; it does not automatically represent a class. The project uses classes, objects, and encapsulation without custom inheritance or polymorphism.

Health is a rule, not a prediction

An open risk with impact 4 or 5 gives OffTrack. Another open risk or an overdue unfinished milestone gives AtRisk. Otherwise the project is OnTrack. Likelihood × impact gives a priority score; 20 out of 25 is not an 80% probability.

C# is the language. .NET runs the compiled application and supplies standard libraries. Visual Studio is the editor/build environment. The application stores data in memory, so changes reset on restart.

Questions & commands

Where do I type these?

Visual Studio: open ProjectHealthTracker.slnx and press Ctrl+F5.

Application console: type 1 to list, 2 to view, 3 to update, or 4 to exit. Press Enter after each choice. At selection prompts, 0 cancels.

PowerShell in the repository:

dotnet build ProjectHealthTracker.slnx -c Release
dotnet run --project Tests/TrackerChecks.csproj -c Release
python presentation/build_guide.py
& .\presentation\Start-Guide.ps1

“This console application tracks three fictional projects. Each project has a task, milestone, and risk. I can view projects, change valid statuses, and see health recalculated using C# rules. Data lasts until I close the app.”

Two-minute demo

  1. Start fresh. Type 1: show the three different health categories.
  2. Type 2 → 2: view Inventory and its risk score of 20/25.
  3. Type 3 → 2 → 3 → 2: close Inventory's risk; health becomes OnTrack.
  4. Type 3 → 3 → 2 → 3: complete Training's milestone; health becomes OnTrack.
  5. Type 1: all three are now OnTrack. Type 4 to exit.

Each arrow means press Enter, then enter the next value. The menu does not run these options automatically.
