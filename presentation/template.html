Start with the job, then the code

A person changes a status. C# calculates health. AI explains the risk.

The console application stores three fictional projects. You choose one, view its information, change its task/milestone/risk status, or ask local Qwen for an explanation. The two classes divide those jobs.

Four names, four different jobs: C# is the language the application is written in. .NET supplies the runtime that executes it and reusable libraries such as HttpClient. Visual Studio is where you edit, build and run the application. Bionic runs the separate local model service that the application contacts.
Our class · Project

One project’s data and rules

A class defines what an object can hold and do. Project defines properties such as Name and RiskStatus, plus methods such as CalculateHealth().

new Project(2, "Inventory System", "Taylor Smith") creates one object using that definition. Its values belong to that object; another Project can have a different name and status.

Our class · Program

The sequence of actions

Main() is the method where execution begins. Program creates the sample objects, repeats the menu, reads your choices, calls the Project methods and communicates with Bionic.

Its methods are static: we call them without creating a Program object. A Project’s health method is an instance method: it uses the values belonging to one particular Project.

Your opening sentence

“Project defines the information and rules for one project. Program controls the menu and the local AI connection. C# decides the health category; AI adds an explanation of the supplied risk.”

Read one line without guessing what the words are

List<Project> projects = CreateSampleProjects();
List<Project>
The type: a .NET list whose entries refer to Project objects. The angle brackets specify the element type. This is not a method.
projects
A variable name. It holds a reference to the list. A reference is how the program reaches an object; it is not a new copy of the object.
=
Assignment: evaluate the right-hand side, then place its result in the variable on the left. It is different from ==, which compares two values.
CreateSampleProjects()
A method call. Run this named set of instructions. The empty parentheses mean the caller provides no arguments. The method returns the list.
;
The end of this statement. It does not mean the entire program has finished.

The problem and the two roles

“This is a console project-health tracker using fictional classroom data. Each project has one task, one milestone and one risk. Project is the class that defines its data and rules. An individual Project object holds one project’s values. Program is the other class; it handles the menu, input, output and local AI connection. These classes work through method calls; they do not inherit from each other.”

0:45–1:45 · Main, sample construction and the menu

Show where execution begins

“Execution starts in Main. In List<Project> projects = CreateSampleProjects(), List<Project> is the type, projects is a variable, and CreateSampleProjects is the method being called. The right side runs first, then its list result is assigned. new Project creates each object; the constructor sets its ID, name and manager, and an initializer fills the other properties. The list holds references to those objects.”

“Main creates one HttpClient for later HTTP requests. A while loop repeats the menu. ReadLine returns text, and switch chooses which method to run. break leaves the switch; return from Main exits the application.”

1:45–3:00 · UpdateStatus, ChangeStatus and CalculateHealth

Trace a value rather than reciting method names

“To close Inventory’s risk, I choose menu three, project two, section three, and status option two. ReadLine returns the string two. TryParse produces integer two. The allowed list is Open and Closed, at indexes zero and one, so subtracting one selects Closed. That enum value is different from both the menu number and list index.”

“ChangeStatus checks the allowed list again, assigns RiskStatus on the existing object, and returns true. Its private setter prevents a direct status assignment from Program. CalculateHealth then checks the current properties in order. An open impact-four-or-five risk is OffTrack; otherwise an open risk or overdue unfinished milestone is AtRisk. Otherwise it is OnTrack. The score is likelihood times impact, but it is not a failure probability and does not decide that health category.”

3:00–5:30 · The local AI integration

Point to the request and follow its return path

“The AI runs in Bionic’s local runtime, outside the C# process. I configured the loopback address and model key. The key identifies Qwen; it is not an API credential. A model file being downloaded is not enough: the API must be listening and an instance must be loaded.”

“ReviewRiskAsync selects an open risk, previews the facts and confirms the request. ExplainRiskAsync receives the client and the selected Project. Its readiness helper sends GET to /api/v1/models, matches the model key and returns a loaded instance ID. If there is no ID, chat is not sent.”

“I build a prompt from the project name, calculated health and risk details. An anonymous request object puts that text in input and instructions in system_prompt. JsonSerializer.Serialize converts the object to JSON text. StringContent packages that text as UTF-8 application/json content.”

“The actual generation call is client.PostAsync with the chat URL and body. It returns Task<HttpResponseMessage>; await gives me the completed response object. I check its status, read its content as text and parse the JSON. The loop takes only output entries whose type is message. I collect their content, return a string, and ReviewRiskAsync prints it with WriteLine. The menu waits until this finishes.”

“AI supplies an explanation and suggested action. It cannot update the project through this code because no assignment applies its output to the Project properties. Prompt instructions request accurate wording, but do not guarantee it. Expected HTTP, timeout and JSON failures become readable messages.”

5:30–8:00 · Demo and close

Demonstrate the behavior you just explained

“I’ll show the starting health categories, close Inventory’s risk, complete Training’s overdue milestone, and show that all projects are OnTrack. Then I reopen Inventory’s risk and request the local explanation. The generated wording can vary, while the C# health stays OffTrack.
