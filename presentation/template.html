“My program tracks a project and explains its risk.”

It stores fictional information, lets you change a status, and calculates project health. A local Qwen model adds a written explanation of the risk.

Say this first

“Project holds the data and rules. Program handles the interaction. C# calculates health; the local AI explains the supplied risk.”

The deliberate limit: one task, one milestone, and one risk per project. There is no ProjectItem class or separate item ID. In the status menu, 1 = task, 2 = milestone, 3 = risk. Neither application class is a custom parent class of the other.

Keep these words straight

Class
A definition. Project says what each project can hold and do.
Object
One actual thing made from a class. Inventory System is the Name of one Project object.
Variable
A name holding a value or a reference. selectedProject refers to the Project object the user chose.
Property
A value on an object. selectedProject.RiskStatus reads that project's risk status.
Method
An action you call. CalculateHealth() runs instructions and returns a result.
Enum
A type with named choices. ItemStatus is the type; ItemStatus.Closed is one value.

A reference is a way to reach an object. Two variables can refer to the same object. Changing it through one variable changes what the other sees.

C# is the language; .NET supplies reusable classes and runs the app; Visual Studio helps edit, build, and debug. Bionic runs the local AI connection separately. A .cs file is a C# source file, not necessarily a class: StatusTypes.cs contains two enums.

Opening · show Program.cs

The problem and the two roles

“My project is a console-based project health tracker. It uses fictional classroom data. A task is a piece of work, a milestone is a checkpoint, and a risk is a possible problem. I limited each project to one of each so the design would be easy to explain. Project holds the data and rules. Program handles the menu, typed input, and local AI connection.”

Start → create data → menu

Main starts the application

“Execution begins in Main. CreateSampleProjects makes three Project objects and returns a list. In List<Project> projects, the first part is the list type and projects is the variable holding its reference. new Project calls a constructor, which sets the starting ID, name, and manager. The other properties hold the project's task, milestone, and risk information. These are separate values on each project object.”

“Main also creates one HttpClient for local requests. Then while repeatedly displays the menu. ReadLine gets text from the keyboard, and switch chooses which method to call. A method returns to its caller when it finishes. The program exits when option five returns from Main.”

UpdateStatus → ChangeStatus → CalculateHealth

Show one change

“UpdateStatus has three blocks: select a project and section, choose a valid status, then apply the change and display health. Section three means risk. GetAllowedStatuses returns Open and Closed. The menu displays them as one and two, but list positions start at zero, so the code subtracts one from the selected number.”

“ChangeStatus checks the choice before assigning RiskStatus. Its private setter prevents other code from assigning that status directly. The selected project is the same object in our list, so the new value is visible immediately. CalculateHealth uses the current values: an open risk with impact four or five means OffTrack; otherwise an open risk or overdue unfinished milestone means AtRisk; otherwise OnTrack. The priority score multiplies likelihood and impact, but is not a probability and does not decide health.”

Spend the most time here · Program.cs local AI methods

Explain the actual AI call

“I integrated the model through Bionic's local API. An API is how programs communicate. BionicUrl points to this computer, and ModelKey identifies Qwen 3.5 9B. The runtime must already be running with the model loaded. This app sends no training or download request.”

“ReviewRiskAsync selects a project with an open risk, previews the facts, and asks for confirmation. ExplainRiskAsync receives our HttpClient and Project objects. GetLoadedModelAsync first sends a GET request to the models endpoint and finds a loaded Qwen instance. A downloaded file alone is not enough.”

“I build a prompt containing the fictional project name, calculated health, and risk details. JsonSerializer.Serialize turns the request object into JSON, structured text the API understands. StringContent wraps it as the request body. The exact call that asks for an answer is client.PostAsync with the local chat URL and that body. await waits for the request to finish before we read its response.”

“The response is also JSON. I find the output entries marked message and collect their content. The method returns the text, and ReviewRiskAsync prints it with Console.WriteLine. The model's reply does not change the project's ratings, status, or health. The menu waits during the request; expected failures become readable messages.”

Close with the tradeoff

Explain why it is small

“This is a fixed classroom demonstration, so I used two application classes and data that resets on restart. Supporting several risks per project or saving data would require extending the design. The AI produces advice, not a measured probability of project failure. Its wording can be inaccurate, so it is displayed for review rather than applied automatically.”
